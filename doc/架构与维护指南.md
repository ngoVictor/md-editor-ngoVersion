# md-editor 架构与维护指南

版本字段 `0.1.0`。本文描述当前代码归属及变更契约；产品见 [PRD](PRD.md)，精确门禁见[能力边界与限制](能力边界与限制.md)。根 [AGENTS.md](../AGENTS.md) 保持为项目指令入口。

## 1. 运行入口与依赖方向

TypeScript + Vite，无 UI 框架，Vditor 3.11.2 负责编辑。Tauri 2/Rust 提供文件、历史、资源和原生窗口能力，正式 Windows exe 嵌入前端资源，依赖 WebView2 Runtime。

| 入口 | 生命周期 |
| --- | --- |
| [index.html](../index.html) → [main.ts](../src/main.ts) | 编辑窗口组装；注册钩子、文档/偏好/会话/保存/导出/导航、单实例接收、拖放与关闭 |
| [preview.html](../preview.html) → [source-preview-main.ts](../src/source-preview-main.ts) | 独立源码预览；不启动 Vditor、docs、session 或 autosave |
| [lib.rs](../src-tauri/src/lib.rs) / [main.rs](../src-tauri/src/main.rs) | 原生启动、插件、命令注册、应用数据目录与窗口销毁清理 |

业务模块依赖纯函数、store、同步边界和服务适配；底层不反向依赖 main。`S` 是窗口内共享状态，不是跨 WebView 的共享内存。文档写入口集中在 store；刷新通过回调/注册表，store 订阅供会话、最近文件和状态 UI 使用。import 图的真实边界由 [architecture.spec.ts](../tests/architecture.spec.ts) 检查，不能把示意分层理解成所有模块之间均无直接依赖。

## 3. 文档状态与编辑契约

`Doc` 包含身份 path/pathKey/name、content/revision、savedContent/fingerprint/mtimeMs/size、dirty/pendingInput/saveState、loadState、外改与错误状态，以及编辑/预览滚动位置。

- 正文事务使用 `applyDocumentEdit` → store；不直接赋值 content 或绕开 revision。撤销按内容与 savedContent 重新计算 dirty。
- `mountDocument` 用 suppressInput 回填并记录渲染值。若 Vditor 规范化后值没有进一步变化，不把它写回原始正文。
- input 使用 `scheduleEditorSync`，大文档延迟；定时器绑定 docId 和挂载 generation。主动保存/切换/导出需 `syncDocFromEditor` 强制同步。
- 用户清空允许回写空串；被动快照保留空读守卫。所有程序性 setValue 包裹 `withSuppressInput` 的 try/finally。
- IME 合成、编辑器重建和窗口转移期间，相关入口拒绝不安全操作。模式/语言由末次意图队列重建，after 业务通过钩子注册进入，不反向 import docs。
- 普通重复打开：dirty 保留正文与基线，clean 用 `replaceDocumentFromDisk` 同时替换；异步读取返回前复核 revision、磁盘基线及保存状态，过期结果只激活。当前标签重复激活只同步，不重新挂载。已加载文档链接通过 Rust pathKey 查找，只激活，不读盘覆盖草稿。
- lazy 载入仅向仍在集合且身份一致的文档提交；只有它仍激活时挂载。导航另核对请求代次、源 revision、激活代次和编辑器实例。

## 4. 保存、另存为、历史与恢复

保存顺序：等待该文档前次请求 → 同步激活编辑器 → 选择候选路径/目标基线 → 确认空白 → 捕获正文/revision → 必要时迁移图片 → Rust 检查/归档/写盘 → store 提交磁盘身份。

`saveTails` 保证每文档严格串行；窗口内按 Rust pathKey 预留保存目标，防止不同文档并发抢占同一路径，已打开但磁盘缺失的路径也不得由另存为占用。路径选择、确认、资源迁移等等待后重新核对输入门禁和文档有效性；Rust SAVE_LOCK 进一步串行文件保存。Rust 写前和 rename 前核对 expectedFingerprint，覆盖旧字节前归档历史；唯一同目录临时文件 create_new、write、sync_all、rename，失败清理；写后核验本次内容。只有明确确认冲突才传 force，后台保存不 force。

`commitSavedDocument` 保留捕获的 savedContent；revision 不同或 pendingInput 时 dirty 保持，写盘等待中开始的合成输入也标记为未保存。关闭标签/窗口先暂停后台保存并等待保存队列排空，等待中追加的请求也必须结束；即便开始时没有 dirty 标签也要等待。选择保存须循环直到当前内容落盘。

另存为的目标 path/pathKey/name/fingerprint 在成功前保留为局部候选。`migrateImages` 只返回改写内容，save 在事务中核对 revision 后提交；复制期间编辑则拒绝新身份。若副本已写盘，明确提示保留旧路径并重新另存为。成功时撤销/重做中的旧相对图片引用重定位到原目录，防止撤销读错图片。资源失败遗留的内容寻址文件不自动删。

文件历史与内存撤销分离：Rust 保存原始字节和编码元数据到应用 local data 的 history-v1，归档失败阻止覆盖；history-view 恢复通过编辑事务，并设置暂停后台保存状态。会话只保存路径/激活项，不持久化正文；拆分窗口不得覆盖主会话。

## 5. 导出管线

| 模块 | 职责 |
| --- | --- |
| [export.ts](../src/export.ts) | 格式注册、统一入口忙碌状态，具体后端不操作工具栏 |
| [export-snapshot.ts](../src/export-snapshot.ts) | 同步捕获 docId/revision/name/sourcePath/markdown/html；冻结快照和输入门禁 |
| [export-assets.ts](../src/export-assets.ts)、[export-specials.ts](../src/export-specials.ts) | inert 图片准备、捕获基址、本次缓存/降级；离线公式/Mermaid 栅格化 |
| [docx-tokens.ts](../src/docx-tokens.ts)、[export-docx-token.ts](../src/export-docx-token.ts) | 无 IPC 的 token Word 构建；默认 Word 流程协调 |
| [docx.ts](../src/docx.ts)、[export-docx.ts](../src/export-docx.ts)、[docx-random.ts](../src/docx-random.ts) | 兼容 HTML→docx/OOXML 后处理；流程与美化；依赖所需 randomFillSync 的 Web Crypto 适配 |
| [html-export.ts](../src/html-export.ts)、[export-html.ts](../src/export-html.ts) | 净化和独立 HTML 纯转换；格式/对话框/写盘协调 |
| [export-pdf.ts](../src/export-pdf.ts)、[export-png.ts](../src/export-png.ts)、[export-print.ts](../src/export-print.ts) | 共享快照/图片/净化 HTML，分别协调原生 PDF、隔离 iframe 画布、系统打印 |

默认 Word 先从捕获源码生成受控公式/图表与图片映射，再按 markdown-it token 构建 docx；原始 HTML 采用文本表达。兼容 Word 使用 lute HTML、美化及 JSZip OOXML 后处理。两后端均保持中文字体、代码样式、引用、表格边框和页面列宽契约；错误不静默换后端。

导出不提交文档 identity/dirty；捕获阶段可同步已有编辑。异步等待不得读取新的 activeDoc 或实时 DOM 代替快照。所有资源只用 sourcePath，失败保留说明，禁远程下载。PDF 使用隐藏禁脚本 WebView2 PrintToPdf，PNG 使用 sandbox iframe + html2canvas；打印只打开系统 UI，不声称实体作业完成。

| [pdf.rs](../src-tauri/src/pdf.rs)、[pdf_webview.rs](../src-tauri/src/pdf_webview.rs) | render_pdf 输入/互斥/临时文件/成品校验/原子提交；PrintToPdf 回调/取消/超时/清理 |

| [resources.rs](../src-tauri/src/resources.rs) | inspect_link_resource/read_link_text/open_link_resource/open_link_in_editor；每次规范化分类、限量解码、参数数组启动 |

| [preview_windows.rs](../src-tauri/src/preview_windows.rs) | open_source_preview/receive_source_preview；preview-* 请求作用域和数量/销毁清理 |

文件/资源 IPC 只放在 file-service；窗口转移 IPC 在 window-transfer，源码窗口请求在 source-preview，启动 IPC 在 main。不要将“所有 invoke 都必须进 file-service”误当作现有规则。

`open-file` 必须 emit_to 一个编辑器窗口，由窗口作用域 listen 接收；StartupFile 兜底监听尚未就绪的启动窗口期。main 不存在时选择 detached；若只剩预览则重建 main，preview/pdf/print 不接收 Markdown 打开事件。

拆分：冻结源窗口并等待保存队列 → clone Doc/历史/模式 → 隐藏目标挂载并报 ready → 源核对快照并 commit → 源移除标签 → 目标 finish 释放载荷。新窗口未提交前源草稿必须保留；不能以从磁盘重开取代转移。

预览：Rust 验证源码类型并登记路径/位置 → 独立 preview.html 按自身窗口取请求 → 只读服务加载。原生标题栏、无 owner、不置顶；主编辑器关闭不关闭预览。预览插件权限仅 close/dialog-open，见 [preview.json](../src-tauri/capabilities/preview.json)；编辑器权限见 [default.json](../src-tauri/capabilities/default.json)。PDF/打印窗口禁脚本、只允许本次临时 URL 导航，不匹配编辑器 capability。

主应用 [CSP](../src-tauri/tauri.conf.json) 允许本地、data/blob 及 HTTP/HTTPS 图片、内联样式、必要 IPC；远程脚本和任意网络 fetch 仍禁用。在线图片由 WebView 的 img 加载，不经过本地图片 IPC，也不参与导出下载。capability 描述的是插件权限；自定义 Rust 命令的类型、路径、尺寸及调用者检查仍须逐项核对，不能据此宣传为操作系统级文件沙箱。

[editor-html.ts](../src/editor-html.ts) 仅为 Vditor WYSIWYG/IR 的顶层块投影配对 HTML 容器的对齐属性，[editor-html.css](../src/editor-html.css) 将净化后的 HTML 预览按正文排版；保留原始 code/source 节点，不包装或移动编辑节点。观察器只监听正文节点变化，不监听自身修饰属性。HTML 输出关闭软换行转硬换行，使链接徽章同行；显示修饰不得进入 Markdown、dirty 或磁盘基线。

## 7. 离线资源、偏好与变更检查

资源由 [copy-vditor-assets.mjs](../scripts/copy-vditor-assets.mjs) 的清单生成，不整目录复制 node_modules/vditor/dist。保留 js/css/images/method.min.js，KaTeX 只留 WOFF2 并移除旧字体 URL，其余运行资源逐字节保留。生成目录不能存用户资源；清理前核验路径/重定向。构建脚本自动生成，Vite 同时产出两个页面。release 使用 s/LTO/单 codegen unit/strip，保留 panic unwind，见 [Cargo.toml](../src-tauri/Cargo.toml)。

偏好按字段写入前合并最新存储，跨窗口 storage 同步；主题 palette/appearance 与编辑器适配分离，预览复用共享外观，不依赖文档业务。模式/语言重建和 setTheme 均指定本地主题资源。

修改前先确定所属模块，再按相关风险验证：保存/身份需 data-safety/integration/p4-p5；导航需 links/navigation-export/resource-links；表格/多窗口需 table-window 和正式 exe；Word/图片需 docx/export-assets/p4-p5 及真实 Word；主题/资源需 themes/offline-assets/资源清单测试。完整命令和 Windows 手工项见[构建说明](构建exe全流程.md)。
