## Word 两后端的区别

默认 token 后端由 docx-tokens 建结构，不套用兼容后端所有 HTML hack。保留原生脚注/编号、表头、中文字体及 A4 表格宽度；原始 HTML 用文本表达，复杂 HTML 用户可选兼容后端。

以下经验**仅针对兼容 html-to-docx@1.8.0 管线**：

- 依赖 events/buffer/stream/util/process 的浏览器 polyfill、globalThis 和 JSZip 预构建；这些不是无用配置。
- crypto 别名只实现图片关系 ID 所需 randomFillSync，不是完整 Node crypto；依赖升级复验图片关系及浏览器构建。
- HTML margin 会被生成的 w:spacing 覆盖，段距/中文字体/代码底纹/边框/列宽由 OOXML 后处理完成，不插空段补间距。
- 代码按行拆 pre 并保留空格，避免换行缩进被转换器吞掉。
- JSZip 统一读取 blob.arrayBuffer；Buffer/Uint8Array 需注意 offset，不能直接拿整个底层 buffer。

两后端都要检查显式边框、tblGrid/tcW 及总列宽。XML 合法只能证明结构可解析，不能代替真实 Word/WPS 排版检查。

## 验证环境的陷阱

Windows 含 & 的 npm scripts 路径、MSVC 初始化和 Node 24 的 Vite 子进程回收，按[构建说明](构建exe全流程.md)处理。Playwright fake 失效时先重启自己管理的 Vite 检查 HMR 模块重复，不先改保存逻辑。等待平滑滚动完成后再判断位置。

原生脚本按版本理解：r4 页面内预览的断言不适用于 r5 以后独立窗口。归档里的 probe/prepare/save-probe 是固定基线实验，不能当当前产品测试执行。不要为通过测试扩大 capability、连接用户 WebView2 profile 或结束用户 Word/编辑器进程。
